# DuoDone v2 💞

Гейміфікований трекер спільних побутових справ і звичок для двох партнерів (пари, сусідів, друзів або родичів) із підтримкою **Telegram Mini App (iOS, Android, Desktop)** та **мобільних браузерів (iOS Safari, Android Chrome, PWA)**.

---

## Архітектура та рішення під iOS / iPhone

1. **Жодного `localStorage` для стану чи фото:**
   - Усі простори, учасники, задачі, лічильники, логи, рулетка та налаштування зберігаються на сервері в SQLite (`WAL`-режим, `FOREIGN KEYS`, транзакції `BEGIN IMMEDIATE`) через вбудований модуль `node:sqlite`.
   - Клієнт тримає лише токен сесії (`dd_token`) та ID поточного простору (`dd_space`) з in-memory фолбеком для приватного режиму Safari.
   - Для браузерного режиму передбачено **Ключ відновлення (`XXXX-XXXX-XXXX`)**, що захищає від 7-денного ITP-очищення в iOS Safari.
2. **Фотографії — тільки через Object Storage / файлове сховище:**
   - Клієнт стискає зображення на `<canvas>` до `≤ 1200px` по довгій стороні (`JPEG 0.8`), з автоматичним врахуванням EXIF-орієнтації iOS та примусовим вивільненням пам'яті Canvas/ObjectURL.
   - Вибір фото використовує `<input type="file" accept="image/*" multiple />` **без `capture="environment"`**, щоб у Telegram WebView на iOS працював вибір і з галереї, і з камери.
   - Підтримуються два драйвери сховища (`server/src/storage.ts`): локальний диск (`/uploads/*`) або будь-яке S3-сумісне хмарне сховище (**Cloudflare R2, AWS S3, Supabase Storage S3, MinIO**). У БД зберігається лише URL.
3. **Верстка та UX під iOS:**
   - `100dvh` + `viewport-fit=cover` + безпечні відступи `env(safe-area-inset-top/bottom)` і змінні Telegram `--tg-safe-area-inset-*`.
   - Усі `input`, `textarea`, `select` мають `font-size: 16px`, що виключає авто-зум iOS Safari при фокусі.
   - `touch-action: manipulation`, `-webkit-overflow-scrolling: touch`, `overscroll-behavior: contain`.
   - Усі виклики `Telegram.WebApp` обгорнуті в безпечні перевірки (`client/src/lib/tg.ts`).
4. **Синхронізація та заборона кешування:**
   - Кожна відповідь API віддається з `Cache-Control: no-store, no-cache, must-revalidate`.
   - Миттєве оновлення між партнерами через WebSocket (`/ws`) + автоматичне оновлення при поверненні вкладки з фону (`visibilitychange`, `pageshow`, `online`).

## Швидкий старт

Вимоги: **Node.js >= 22.13**.

```bash
# 1. Встановити залежності
npm install

# 2. Запустити в режимі розробки (сервер :3001 + Vite :5173 з проксі)
npm run dev
```

Відкрий `http://localhost:5173`.

### Продакшн-збірка та запуск

```bash
npm run build
npm start
```

Сервер запуститься на `http://localhost:3001` і роздаватиме зібраний фронтенд (`client/dist`), REST API (`/api/*`), WebSocket (`/ws`) та завантажені фото (`/uploads/*`).

### Перевірка типізації та приймальні тести

```bash
npm run typecheck
npm test
```

`npm test` (`server/test/acceptance.ts`) автоматично перевіряє всі сценарії з розділу 5 ТЗ:
1. Створення простору «Дім», перейменування на «Діма» і «Віка».
2. Вхід Віки за інвайтом через HMAC-підписаний `Telegram.WebApp.initData` та перевірка, що кастомні імена «Діма» і «Віка» **не перезаписуються** даними з профілю Telegram при повторних входах.
3. Створення простору «Пара Олега» третім користувачем (Олегом) і запрошення Віки.
4. Перевірка мульти-просторовості та суворої ізоляції: Віка бачить 2 простори («Дім» і «Пара Олега»), Діма бачить лише «Дім», Олег — лише «Пара Олега», а 3-тя стороння особа при спробі входу в заповнений простір отримує `403 space_full`.
5. Завантаження 2 фото та виконання задачі з миттєвим відображенням у партнера.
